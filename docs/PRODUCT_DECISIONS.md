# 产品需求与决策记录

本文记录“日进·拾光（Grow with Time）”需求的新增、调整、暂缓和放弃。

它解决两个问题：

1. 避免后续开发继续按照已经失效的旧需求修改代码。
2. 让产品取舍、验收标准和技术实现保持一致。

README 描述当前产品；本文解释需求为什么发生变化。两者冲突时，应先确认本文中日期最新且状态为“已确认”的决策，再同步更新 README、代码文案和测试。

## 状态定义

- **提议**：正在讨论，不能作为开发承诺。
- **已确认**：进入实现与验收范围。
- **已调整**：保留目标，但范围或方案已经变化。
- **已暂缓**：现在不做，未来可以重新评估。
- **已放弃**：退出产品范围；未经新的产品决策，不得继续实现。
- **已替代**：由另一项需求或方案接管。

## 维护规则

- 每次需求方向、产品边界或关键验收标准发生变化时，在本文件顶部新增记录。
- 记录必须包含：状态、原因、当前验收标准和代码影响。
- “已放弃”的需求不保留模糊文案、隐藏开关或后台自愈逻辑。
- 普通缺陷修复不必逐条记录；只有会改变用户预期或技术方向的修改才记录。
- 发布前检查 README、设置页和 Release Notes 是否与最新决策一致。

## 决策日志

### PD-2026-09-01-02：数据库只支持向前升级

- **日期**：2026-09-01
- **状态**：已确认
- **背景**：SQLite migration 一旦执行即成为本地数据契约；安装旧版本可能缺失已经执行过的 migration，导致应用无法启动或错误理解新数据。
- **当前产品定义**：正式安装包只支持同版本重装或升级，不承诺从高版本降级到低版本。
- **当前验收标准**：
  - 已发布的 migration 编号与内容不可删除、重排或改写，只能新增更高编号。
  - 发布说明明确标注“不支持降级安装”；用户需要回退时，应先导出兼容备份并卸载/清理数据后再安装旧版。
  - 发布前运行 migration 契约测试，并用上一正式版本数据库验证升级。
- **代码影响**：migration 保持追加式；不通过删除历史 migration 来修复问题。

### PD-2026-09-01-01：放弃 Win+D 后桌面组件持续显示

- **日期**：2026-09-01
- **状态**：已放弃
- **原需求**：桌面组件像 Windows 系统便签一样固定在桌面，按 Win+D 后仍持续显示，不依赖消失后的轮询拉回。
- **变更原因**：Explorer/WorkerW 固定、独立宿主和 WebView2 组合明显增加崩溃、残留进程、数据同步、开发与发布不一致等风险。该能力的维护成本和稳定性风险高于实际收益。
- **当前产品定义**：
  - 桌面组件是普通桌面浮窗。
  - 支持“贴窗口底层”和“始终置顶”两种模式。
  - 不保证按 Win+D 后仍显示。
  - 不使用 WorkerW/SetParent、独立桌面宿主或轮询自愈来实现 Win+D 常驻。
- **当前验收标准**：
  - 组件能够正常显示、隐藏、拖拽、缩放和交互。
  - 置顶/置底选择在主窗口关闭、重新打开后不应被代码擅自改变。
  - 组件失败不得导致主程序崩溃或留下孤儿进程。
  - 设置页、README 和发布说明不得再承诺“Win+D 常驻”或“自动恢复”。
- **代码影响**：继续使用 Tauri WebView 窗口承载组件；窗口层级代码只负责置顶/置底，不负责加入 Explorer 桌面层。

### PD-HISTORY-04：安装包优先最小、离线和稳定

- **状态**：已确认
- **结论**：Windows 使用尽量精简的 NSIS 安装包；安装过程不联网下载运行时，不内置 WebView2。极少数缺少 WebView2 的系统由用户自行安装。

### PD-HISTORY-03：产品采用双主线结构

- **状态**：已确认
- **结论**：“日进”负责每日执行与成长，“拾光”负责灵感、今日收获和未来信；不继续横向增加第三条大产品线。

### PD-HISTORY-02：中文品牌与英文名并存

- **状态**：已确认
- **结论**：中文品牌为“日进·拾光”，英文产品名始终保留为“Grow with Time”。安装包、窗口标题、仓库介绍和品牌文案不得遗漏英文名。

### PD-HISTORY-01：本地优先的个人工具

- **状态**：已确认
- **结论**：产品面向个人，不发展多人权限、团队协作或重型项目管理；核心数据默认保存在本地 SQLite，无需账号和持续联网。
